# Шаблон поля [Description] UI-расширения

Эталон стиля и структуры — `references/reference_description.md` (описание
расширения 9072 «[аккаунты] назначение ОЛ КУ», записано в карточку и сверено
с сервером; прежний эталон — описание 12221, утрачено при замене файла).

Формат — Markdown с HTML-таблицами. **КРИТИЧНО: HTML-таблицы писать только
построчно** — каждый тег и текст ячейки на своей строке. Таблица «в одну строку»
(`<table><tr><td>...</td></tr></table>` сплошным текстом) запрещена: серверный
редактор может экранировать теги. Единственно допустимый формат:

- `<table><tr><th ...>` — открывающий тег строки и первая ячейка на одной строке,
  но **текст ячейки всегда с новой строки**;
- закрывающие `</th>`/`</td>` и связка `</th></tr><tr><td ...>` — по образцу эталона;
- закрывающий `</table>` — на своей строке.

Порядок и заголовки разделов фиксированы: первый раздел описания — «История
изменений». Обновляя существующее описание, сохраняют нетронутым то, что ведут
люди (История изменений), остальное перегенерируют по актуальному коду расширения.

## Правила наполнения

- Секции описываются в порядке их следования в HTML-вкладке.
- Таблица «Параметр/Значение» каждой секции: `ID` (id из HTML), `Class`
  (классы секции, напр. `section`, `section extra hide`), `Видимость секции`
  (условие из JS-логики; если секция всегда видна — так и писать).
- В таблице «Поля секции» — по строке на каждое поле секции, порядок как в HTML.
  Колонки фиксированы (11), пустые ячейки оставляют пустыми.
- `<c #172b4d>` вокруг значений «не заблокир.» и `<c #a9a9a9>` для серых
  упоминаний имён секций — часть вёрстки эталона; воспроизводить как в эталоне.
- Раздел «История изменений» — всегда первый раздел описания (перед
  «Описание расширения»). Новую запись добавляют строкой вниз, старые строки
  не переписывают. Если у расширения уже есть описание с историей — её
  сохраняют как есть.
- Квадратные скобки в тексте ячеек экранировать: `\[ОИВ\]`.
- Типы полей писать по-русски, как в эталоне: «Справочник», «Целый», «Текст»,
  «Дата и время», «Флажок».
- Источник данных: атрибуты из HTML дословно (`data-custom-view="…"`,
  `data-custom-view-account="…"`, `data-filter-name="…"`) + пространство,
  ограничения ввода (min/max), маски.
- Видимость/Доступность — из логики JS: показ по change другого поля, скрытие
  пустых секций, блокировки полей. Не выдумывать: если поведение неоднозначно,
  писать фактическую формулу кода и осторожную трактовку.
- Повторяющиеся блоки (организация №2…№N) не дублировать строками — описать
  первый блок и отличия остальных.
- Последний раздел тела — «Кнопки и динамическое поведение»: кнопки, хуки
  after-prefill, обработчики change/click, функции show/hide (включая их
  неочевидную семантику: hide ещё и чистит поля через ITRP.clearFormData).
- Если у расширения уже есть описание — раздел «История изменений» сохраняют
  как есть; остальное перегенерируют по актуальному коду.
