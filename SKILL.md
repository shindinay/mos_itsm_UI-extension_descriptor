# Цель

По ссылке на расширение UI от пользователя создать описание
(продукт 4me/Xurrent, инстанс itsm.mos.ru): HTML вкладок, JavaScript и CSS, а
также подготовить описание расширения и записать его в поле `description`
карточки расширения через REST API или создать файл описания в формате .md.

# Источники истины

- Текущая версия платформы: `references/platform.md` (JS API, действия,
  переменные, ограничения). Если она расходится с живым ответом API, приоритет
  у API — платформа дорабатывается последовательно, новые возможности могут
  появиться без обновления этого файла.
- Паттерны кода (jQuery-виджеты, lookup, условная логика, вёрстка):
  `references/patterns.md`.
- Справочник JS API по каждому полю: `references/js_api.md`.
- Список доменов МосИТСМ: `references/mos_domains.md`.
- Формат описания расширения: `references/description_template.md`.
- REST API документация vendor: https://developer.r-service.tech/help/records/ui_extension/ и
  https://developer.r-service.tech/help/fields/ui_extension_fields/

# Входные данные

Пользователь дает на вход ссылку на расширение UI:

- домен МосИТСМ (`references/mos_domains.md`);
- тип записи, к которой крепится расширение (запрос, задача и т.п.);
- какие поля формы и/или вкладки нужны.

Если чего-то не хватает — задай уточняющие вопросы до начала работы. Если
пользователь просит «как в существующем расширении» — скачай это расширение
командой `get` (см. ниже) и работай по его коду, не по догадкам.

# Рабочий процесс

## 1. Уточняющие вопросы
Задай пользователю уточняющие вопросы:
1. В рамках какого запроса требуется добавить описание
2. В каком формате подготовить описание - файл *.md / обновить саму карточку расширения / и то и то
3. Уточни аккаунт ? (в дальнейшем используй полученное значение в вызовах rest api интерфейса)

## 2. Скачивание существующего расширения

```bash
python scripts/ui_extension.py get --ext <ID или URL расширения> [--env QA|PROD] [--out файл.json]
```

В JSON попадают: карточка расширения (`name`, `category`, `title`,
`description`, `description_html`, `disabled`, `form_definition_json`) и код
активной версии (`html`, `javascript`, `css`). История версий:

```bash
python scripts/ui_extension.py versions --ext <ID> [--out файл.json]
```

## 3. Разработка кода вкладок

- HTML — статичная разметка вкладок (Bootstrap-подобные классы, `nav-tabs`,
  `tab-content`). Внутри вкладок размещаются поля формы (`form-group` с
  `data-field`) и контейнеры виджетов (пустые `div` с id).
- JavaScript — логика вкладок и виджетов, загрузка данных через REST API или
  JS API платформы (см. `references/js_api.md`, `references/patterns.md`).
- CSS — стили виджетов и вкладок, если стандартной темы недостаточно.

Правила кода см. в `references/patterns.md`: там же — ограничения платформы
(например, поддержка jQuery определённой версии, запрет внешних CDN и т.п. —
сверяйся с актуальной версией `platform.md`).

## 4. Описание расширения (description)

Формат описания: `references/description_template.md`, эталон структуры и
стилистики — `references/reference_description.md` (описание расширения 58).
Первый раздел описания — всегда «История изменений» (дата, запрос РП/ЗНИ, суть
изменения; новые записи добавляются вниз, старые не переписываются). Далее
тело описания делится на три главных раздела (H1): «О расширении» — с
подразделами «Использование» и «Особенности», «Спецификация» — на каждую
секцию вкладки `### Секция "<заголовок>"` с таблицей «Параметр/Значение» и
таблицей «Поля секции», «Элементы управления (кнопки и динамическое
поведение)». Все таблицы — как в шаблоне: каждый тег
`<table>`, `<tr>`, `<td>` и текст ячейки на своей строке, иначе серверный
рендерер экранирует разметку (проверка есть в скрипте, команда `check`).

Порядок работы:

1. Заполни шаблон по факту готового кода (не по плану).
2. Сохрани описание в `artifact/desc_<ID расширения>.md`.
3. Запиши в карточку:

```bash
python scripts/ui_extension.py set-description --ext <ID> --file artifact/desc_<ID>.md --dry-run
python scripts/ui_extension.py set-description --ext <ID> --file artifact/desc_<ID>.md --yes
```

Перед записью `set-description` делает бэкап текущего расширения в
`backups/uiext_<ID>_<дата>.json`. Флаг `--dry-run` показывает, что будет
записано, без отправки PATCH. После записи скрипт сразу сверяет `description`
с файлом и разметку `description_html`.

4. Если пользователь не просил обновлять карточку — просто покажи готовый
   markdown и сохрани файл, API не вызывай.

## 5. Проверка после записи

```bash
python scripts/ui_extension.py check --ext <ID> --file artifact/desc_<ID>.md
```

# Ограничения

- дефолтная среда — из `.env` (`MOSITSM_STAGE`, сейчас QA); переопределяется флагом `--env QA|PROD`;
- аккаунт по умолчанию — `community`;
- скрипт не создаёт новые расширения и не активирует версии — только чтение
  (`get`, `versions`, `list`), запись описания (`set-description`) и проверка
  (`check`);
- токены и URL — в `.env` (`MOSITSM_PERS_TOKEN_QA` / `MOSITSM_PERS_TOKEN_PROD`,
  `MOSITSM_API_URL_QA` / `MOSITSM_API_URL_PROD`). Токен PROD замаскирован —
  для PROD пользователь передаёт токен явно (--token) или заполняет `.env` сам;
- нельзя удалять/архивировать расширения через этот скилл — только чтение,
  описание и новые версии;
- все временные файлы — в `temp/`, итоговые — в `artifact/`, корень проекта
  держать чистым;
- не выдумывай ID расширений и ссылки: если данных не хватает — спроси.
